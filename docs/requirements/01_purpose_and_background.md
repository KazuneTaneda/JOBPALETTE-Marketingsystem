# 01. 目的と背景

## 目的

現在、求人広告（求人ボックス・Indeed・Engage・ジモティ等）の応募者データは、必要になる都度、人が確認・集計してから判断している。
これを以下の状態に変える。

```
ローデータ蓄積 → 自動分析 → 週次レポート生成 → 人間は意思決定だけ
```

毎回 Claude や ChatGPT にファイルを投げて分析するのではなく、放置していてもレポートが生成される状態にする。

## 背景にある考え方

「AI で浅い分析だけして終わるのではなく、7割程度までは自動化して、人間が最後の深い意思決定をする」。

- 今は分析の深さが「2層目くらい」で止まっている
- Before: 人間 → データを探す → 数字を確認する → 原因を考える → 判断する
- After: AI（データ収集 → 集計 → 異常検知 → 原因候補 → 改善案）→ 人間（意思決定）

## スコープ（2フェーズ構成）

本要件定義が対象とするのは **フェーズ1** のみ。

| フェーズ | 内容 | 本要件定義の対象 |
|---|---|---|
| フェーズ1 | データ基盤・自動分析・週次/月次振り返りレポート・求人改善提案 | **対象** |
| フェーズ2 | 上流の月次戦略計画（来月どの媒体・アカウント・求人にどう配分するか）の自動化 | 対象外。フェーズ1稼働後、見えた課題を踏まえて別途要件定義する |

フェーズを分けた理由: 先に実績データと振り返りの型を作り、そこで明確になった課題（例:「どの媒体・アカウント・求人で何が起きているか」「何が効いていないか」）を踏まえてからでないと、月次計画の自動化は設計しても的外れになりやすいため。

## 対象事業

1. **求人広告マーケティング**（本要件定義のメインスコープ）
   - 媒体: 求人ボックス、Indeed、Engage、ジモティ（基本これらが中心）
2. **人材紹介事業のKPI可視化**（[05 KPI定義](05_kpi_definitions.md) の一部として扱う）
   - 応募 → IS → 面談設定 → 面談実施 → 推薦 のファネルを可視化
   - 営業利益率15%が存続ラインという前提を踏まえた数字の見える化

## 関連システム: dr-system

[dr-system](https://github.com/KazuneTaneda/dr-system) はダイレクトリクルーティング（送信枠・Target・Search・Copy・Allocation）の月次計画・実績管理システムで、現在要件定義フェーズにある。
対象データもドメインも異なるため本システムとは別リポジトリ・別システムとして独立に構築するが、以下の進め方・思想を共通で踏襲する。

- 要件定義を文書化してレビューしてから実装に着手する
- 「実績を蓄積するほど、次の意思決定が楽になる」データ構造を目指す
- 月次サイクル（実績 → 振り返り → 次月への示唆）を軸にする
