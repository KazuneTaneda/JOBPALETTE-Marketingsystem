# 02. 現状と課題

## As-Is

- 必要な数字が発生するたび、人が該当データを探し、集計し、確認してから判断している
- 分析するときは都度 Claude や ChatGPT にファイルを投げている（分析結果が蓄積・再利用されない）
- 媒体（求人ボックス・Indeed・Engage・ジモティ）のデータは期間を区切らず一元蓄積されておらず、分析の起点ごとにデータを揃え直している可能性が高い
- 求人ボックスは**過去60日分のキーワード別・求人別CSV**が入手できることがわかっている（60日ローリングと見られる）。他媒体（Indeed／Engage／ジモティ）が同様の形式・粒度・提供期間か、CSVが手動DLかAPIかは未確認 → [09 Q-02](09_open_questions.md)
- 60日ローリングという制約がある場合、取込を放置すると60日より前のデータが失われる。「期間を区切らず一元蓄積」を実現するには定期的な取込・差分の積み上げが必須

## 課題

### 1. 分析が浅い（2層目で止まっている）

現状の分析は「媒体別に応募数やCPAを見る」程度の層で止まっており、

```
媒体 → アカウント → 求人 → 応募者属性
```

まで掘り下げて「どこから35歳以下の応募が来ているのか」を特定する分析ができていない。

### 2. CPAだけでは評価を誤る

CPAの高低だけで求人・媒体・アカウントを評価すると、35歳以下の有効応募が取れている媒体を誤って「悪い」と判断してしまう。単純な高低ではなく、35歳以下有効応募率とセットで評価する必要がある。

### 3. 求人文言が機能しているか検証されていない

「20代活躍中」と求人に書くだけでは若年層フィルターとしてほぼ機能していない求人がある、という認識が既にあるが、タイトル・仕事内容・給与・勤務地・職種・媒体・アカウントなど、どの特徴量が若年層の応募に効いているかは特徴量として分析されていない。

### 4. 異常検知が属人化している

「シニアが異常に多い求人」「外国籍応募が偏る求人」のような異常は、人が個別に気づいて初めて認識される状態で、自動検知の仕組みがない。

### 5. 人材紹介側の工程可視化が不十分

応募 → IS → 面談設定 → 面談実施 → 推薦 の主要工程のうち、特に日次稼働・推薦数・面談設定数・面談実施数がHubSpot等から定常的に拾えていない（想定: 中間工程は後回しでよいが主要工程は必須）。

## 既に見えている仮説（要検証）

分析基盤ができ次第、以下の仮説を定量的に裏付ける／反証することが初期の分析タスクになる。

- WorkEdge は35歳以上応募が比較的少なく、35歳以上比率は約20%
- MIRIZE／Assist／Openpath は35歳以上応募がかなり多い
- 「20代活躍中」等の文言だけでは若年層フィルターとして機能していない求人がある
