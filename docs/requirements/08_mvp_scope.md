# 08. MVPの範囲（ドラフト）

技術構成・データ入手方法が未確定のため、確定後に見直す前提の初稿。

## Must（最初に作るもの）

- 求人ボックス（最優先媒体と推測）のローデータを一元蓄積できる取込フロー
- A系（総論: 媒体／アカウント単位）の基本指標の自動集計
- 35歳以下有効応募率を中心とした評価ロジック（CPA単体評価にしない）
- 週次レポートの自動生成（最低限の項目セット、[05 KPI定義](05_kpi_definitions.md) 参照）

## Should（MVPの直後）

- Indeed／Engage／ジモティのデータ取込への拡張
- B系（各論: 求人単位）の異常検知（シニア過多・外国籍偏重）
- 改善アクション案の自動生成
- 人材紹介ファネル（HubSpot連携）の主要工程可視化

## Could（余裕があれば）

- 求人の特徴量（文言・給与・勤務地等）と35歳以下応募率の相関分析
- レポートの自動配信（Slack／Notion等、[09 Q-03](09_open_questions.md) 確定後）

## Not Now（フェーズ2以降）

- 月次戦略計画の自動生成（来月の配分・追加求人本数の提案等）
- dr-system のような Version 管理を伴う求人テンプレート／ターゲット条件の資産化
