# 10. 求人ボックス キーワード別分析の設計（媒体別分析の第一弾）

[03 To-Be業務フロー](03_to_be_workflow.md) の「媒体 → アカウント → 求人 → 応募者属性」の掘り下げを、求人ボックスで具体化したもの。他媒体（Indeed／Engage／ジモティ）でも同様のデータが取れ次第、同じ型を横展開する。

## 背景

- 求人ボックスは公開情報ではCMによる認知拡大と、膨大な求人を一括検索できる利便性を訴求している
- 検索・CM・広告経由など、流入経路の比率は公開情報だけでは分からない
- 一方、**自社アカウントの「キーワード別」「求人別」レポート**はCSVで取得でき、直近60日分を確認できる。これが実際に打ち手へつなげられる一次情報

## 分析パイプライン（見る順番）

```
検索語句 → 求人ごとのクリック・応募 → 35歳以下の有効応募 → 面談設定 → 獲得単価（CPA）
```

この順で見ることで、以下のような切り分けができる。

- 応募数は多いが35歳以下が少ない検索語句（母集団の質が悪い＝キーワード起点の問題）
- 応募数は少なくても面談につながる求人（効率は良いが露出不足＝求人単体の伸びしろ）

単純な応募数やCPAだけを見ると、この2つを取り違えて誤った予算配分をしてしまう。

## 掲載順位に関する前提

掲載順位は入札額だけでなく、検索語句と求人内容の関連性、求人の品質にも影響される。
したがって、CPAが高い・順位が低いからといって即座に入札額を上げるのではなく、**原稿（求人票のタイトル・仕事内容・ターゲット表現）と検索意図のずれを直す余地がある**、という前提で改善アクションを設計する（[05 KPI定義](05_kpi_definitions.md) のアクション提案ロジックに反映する）。

## 直近のネクストアクション（提案）

1. 運用代行先に「過去60日のキーワード別CSV」「過去60日の求人別CSV」を提出してもらう（[09 Q-02](09_open_questions.md) 参照）
2. 既存の応募者分析（8月1日以降）と求人IDで突合する
3. 突合結果から、求人ボックス内でどこに予算を寄せるべきかを、自社の有効リード基準（35歳以下の有効応募）で判断できるようにする

これは本システムのMVPより前に、手動でも一度実施する価値がある検証ステップとして扱う（[08 MVPの範囲](08_mvp_scope.md) のMust達成前の先行検証）。

## データモデルへの要求

[04 データモデル](04_data_model.md) の `JOB_KEYWORD_STAT` を、`JOB_POSTING`・`APPLICANT`・`REFERRAL_PIPELINE_STAGE` と求人IDで結合できるようにし、次の集計ビューを作れるようにする。

- キーワード × 求人 × (クリック・応募・35歳以下有効応募・面談設定・CPA) のクロス集計
- 「応募数は多いが35歳以下率が低い」キーワードのランキング
- 「応募数は少ないが面談設定率が高い」求人のランキング
